<objective>
Implement the Fade toggle (INTG-01, D-01/D-02/D-03): a new `SystemFilter.fade: bool` field that flips which side of a matched bet gets graded, without ever changing which games get matched. Fade is read exclusively inside `grade_bet`/`_grade_total_bet` (D-03) -- `matches_system` never sees it. This plan delivers the full vertical slice: backend flip logic + CLI parity (Task 1, immediately usable via `python -m cfb_system_maker backtest --fade`), then storage persistence + web UI round-trip (Task 2, the browser-facing toggle near the stat chips per D-01).

Purpose: INTG-01 is the first of Phase 2's two requirements and has no dependency on the Grade computation in 02-02-PLAN.md; it ships first so the file-conflict-driven Wave 2 (Grade) can build on a stable `SystemFilter.fade` field.
Output: `SystemFilter.fade`; fade-aware `grade_bet`/`_grade_total_bet`; `--fade` CLI flag; fade round-trip through `storage.py` and all six `web.py` form/query enumeration sites; Fade toggle checkbox in `templates/index.html`.
</objective>
