## Color

This phase introduces **zero new colors**. Both new elements reuse existing CSS custom properties:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--bg)` `#f6f8fb` | Page background (unchanged) |
| Secondary (30%) | `var(--panel)` `#ffffff` | Fade toggle background (via reused `.check` class), chip `<article>` background (unchanged) |
| Accent (10%) | `var(--accent)` `#166f5b` | Checked-state border/background of the Fade toggle — **free** via the existing `.check:has(input:checked)` rule (`styles.css:177-181`), triggered automatically because the toggle reuses the `.check` class verbatim. No new accent usage is introduced. |
| Destructive | `var(--loss)` `#b42318` | **Not used by this phase.** Reserved exclusively for its existing uses (negative Margin/Money Won/ROI values, the remove-filter `×` control). Grade letters are deliberately NOT color-coded — see decision below. |

**Design decision — Grade renders as plain text, no per-letter color coding:** The Grade chip's `<strong>` renders the letter from `compute_grade()` (or the em-dash) as plain, uncolored text, matching every other chip's default rendering and the RESEARCH.md reference implementation exactly. Rationale: (1) D-07 scopes this phase to "render the composite Grade value into the existing Grade chip slot only" — no color semantics were requested or decided; (2) the project's only semantic color pair is `--accent` (positive) / `--loss` (negative), reserved for numeric sign (profit/loss) — overloading `--loss` to also mean "bad grade" would conflate two different semantics on the same token; (3) CLAUDE.md's Simplicity First / Surgical Changes rules bias against adding an undecided visual feature. If per-letter grade coloring is wanted later, it is a separate, explicit design decision for a future phase (naturally paired with the deferred sub-score breakdown panel).

Accent reserved for: existing "Run System" implicit submit styling, existing `button` element (`styles.css:183-192`), existing checked-state border/background on any `.check`/`.segmented` control (including the new Fade toggle, via class reuse) — never for Grade letter color.

## Interaction Contract — Fade Toggle

- **Markup:** `<label class="check"><input type="checkbox" name="fade" form="filters-form" {% if form.fade %}checked{% endif %}> Fade System</label>` — reuses the `.check` class verbatim (no new CSS class, no new selector).
- **Placement:** Inside `.workspace-header` (`templates/index.html:220-225`), as a second flex child alongside the existing `<div><h2>Backtest Results</h2>...</div>`, right-aligned via the header's existing `justify-content: space-between`. This satisfies D-01's "near the stat chips" placement without any new layout rule.
- **Submission:** Uses the HTML5 `form="filters-form"` attribute to submit with the existing sidebar `<form>` (which needs `id="filters-form"` added) — no new `<form>`, no client-side JS, consistent with the app's "no frontend framework, full page reload on submit" convention.
- **States:**
  - Unchecked (default): plain `.check` appearance — `1px solid var(--border)` border, `var(--panel)` background.
  - Checked: `.check:has(input:checked)` applies automatically (already-shipped rule) — border becomes `rgba(22, 111, 91, 0.35)`, background becomes `#eef8f4`. No new state styling needed.
- **Persistence:** Checkbox `checked` attribute is driven by `form.fade`, which must round-trip through save/load/tab-switch/remove-filter-link query strings exactly like the existing `theory` field (see RESEARCH.md Pitfall 3) — a UI/backend integration contract, not a new visual state.

## Interaction Contract — Grade Chip

- **Markup (unchanged structure from Phase 1):** `<article><span>Grade</span><strong>{{ grade if grade else "&mdash;" }}</strong></article>` inside the existing `.metrics.stat-chips` section (`templates/index.html:227-233`). Render `grade` through normal Jinja auto-escaping — **no `|safe`**, consistent with the Phase 1 STATE.md rule carried into this phase.
- **States:**
  - No matched bets (`result.bets == 0`): renders `&mdash;` — matches the Margin chip's existing no-data convention.
  - Graded: renders exactly one of `A` / `B` / `C` / `D` / `F` as plain text, same size/weight as every other chip value, no color.
- **No hover/click behavior:** this phase ships the composite value only — no breakdown panel, no tooltip, no interactive affordance on the Grade chip (deferred per CONTEXT.md).
