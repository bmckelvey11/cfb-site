Purpose: this is the phase's landing surface. Every later plan in the phase extends the template and route this plan creates.
Output: `templates/dashboard.html`, a dashboard route plus sparkline helper and figure cache in `web.py`, dashboard CSS, and a test suite re-pointed to the new route layout.
</objective>

**Route relocation (D-09).** Inside `create_app`, rename the existing editor view so it serves `/system`, and register a new view for `/`. Repoint all three `url_for` calls in the `/save` handler at the relocated editor endpoint — including the post-save redirect that carries `load_system`. Missing any of them dumps the user on the dashboard after saving.

**Redirect trigger.** A request to `/` redirects to `/system` with the query string intact when ANY editor filter parameter is present. Define that set explicitly as an allowlist constant: side, bet_type, total_side, favorite, underdog, home, away, fade, min_spread, max_spread, min_total, max_total, filter_seasons, filter_weeks, filter_teams, filter_conferences, filter_providers, the legacy season/week/team/conference/provider aliases, the `ff_` prefixed family, save_name, theory, and load_system.

The trigger must NOT be "a tab parameter is present". The editor already uses that parameter for its own two views and the dashboard uses it for scope, so keying on it would bounce a dashboard request to the editor. Preserve the query string verbatim on redirect so shared links survive.

**Dashboard route.** Follow the existing missing-data degradation pattern: wrap `load_processed_games` in `try`/`except FileNotFoundError` and render the dashboard template with the existing missing-data error state rather than raising. Reuse the editor's existing missing-data copy — do not fork it.

Enumerate systems with `list_systems`, load each with `load_saved_system`, and sort by `saved_at` descending. `list_systems` sorts alphabetically and the UI contract wants most-recently-saved first, so the re-sort happens here.

**Figures (D-11).** For each system, run `run_backtest` ONCE over the full games list, all-time. Derive the selected timeframe's figures from that single result — `season_breakdown` already carries per-season bets/wins/losses/pushes/profit/roi computed by the same path, and `bet_details` filtered on `bet.season` gives the per-season bet set. Do not call `run_backtest` once per system per timeframe tab: it runs a 1000-iteration permutation test plus Wilson CI and grade computation, none of which the dashboard displays, and thirteen season tabs would multiply that cost by fourteen.

Cache results in a module-level in-memory dict keyed by the system's identity (its serialized filter dict) together with the identity of the data files — the size and mtime of `games.csv` and of the features sidecar. A rebuild of the data must invalidate the cache. Never persist a computed figure into saved-system JSON: it would go stale silently after a rebuild.

**Template.** Create `templates/dashboard.html` as a new two-column shell — do NOT reuse the editor's `.app-shell`. The left column holds the page header, tab strips and the systems table; the right column is reserved for the Current Matches panel that Plan 05-06 fills, so leave a clearly marked block for it rather than restructuring later. Columns are `minmax(0, 1fr)` and `minmax(320px, 420px)` with a 32px gap, collapsing to a single stacked column at the existing 900px breakpoint.

Table columns in order: System, Type, Record, Money Won, ROI, Trend. The System cell is a link to the editor carrying that system's load state, with the truncated first line of `theory` beneath it in muted 12px. Type reads Spread or Over/Under with a Fade suffix when the system's fade flag is set — Phase 2 semantics must survive onto the dashboard. Record is neutral. Money Won and ROI use the existing signed-value classes; exact zero gets no color class.

Load NO JavaScript on the dashboard. The editor's filter-modal script is editor-only and must not be referenced by this template. Rely on Jinja's automatic escaping for the system name, the theory text, and every other value; do not disable escaping on any dashboard value.

**CSS.** Extend `static/styles.css` reusing the existing tab, table-wrap, empty-state, positive/negative and panel classes. Introduce no new hex values — every color comes from the existing root tokens.

**Editor back-link.** Add a visible text link back to the dashboard in the editor header of `index.html`. Do not restyle the editor beyond adding this link.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser query string -> dashboard route | Untrusted user-controlled parameters (tab, timeframe, and the redirect allowlist) |
| Saved-system JSON on disk -> dashboard template | System names and free-text theory authored earlier and rendered on a new page |
| Filesystem -> web layer | `games.csv` and the features sidecar may be absent |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-09 | Tampering | stored XSS via system name or `theory` rendered on `dashboard.html` | high | mitigate | Jinja autoescaping on every dashboard value; escaping is never disabled on any of them. A test renders a system whose name and theory contain HTML metacharacters and asserts the escaped form, extending the existing theory-escaping precedent. |
| T-05-10 | Tampering | `tab` / `timeframe` query params used to build a filesystem path | high | mitigate | Both normalize to a fixed known set before use — scope tab to the two known values, timeframe to the literal all or an integer season drawn from the data. Neither is ever concatenated into a path. Unknown values fall back to the default, mirroring the editor's existing normalization. |
| T-05-11 | Information Disclosure | redirect allowlist mis-scoped, leaking editor state or bouncing dashboard traffic | medium | mitigate | The redirect target is the fixed internal `/system` endpoint, never a user-supplied URL, so this cannot become an open redirect. The trigger is an explicit named allowlist, not the presence of the shared tab parameter; a test asserts `/?tab=examples` does not redirect. |
| T-05-12 | Denial of Service | per-system per-timeframe `run_backtest` blowup | medium | mitigate | One all-time `run_backtest` per system, per-season figures derived from `season_breakdown` and `bet_details` (equivalence proven in Plan 05-02), results cached keyed on system identity plus `games.csv` and features-sidecar size and mtime. |
| T-05-13 | Denial of Service | missing `games.csv` crashing the new landing page | medium | mitigate | The dashboard route reuses the existing `FileNotFoundError` degradation pattern and renders the established missing-data state instead of raising. |
| T-05-SC | Tampering | package installs | low | accept | No packages installed; no new runtime or build dependency is introduced by this phase. |
</threat_model>
