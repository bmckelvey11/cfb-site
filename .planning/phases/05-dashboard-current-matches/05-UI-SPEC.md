# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** This phase adds a **new page** — the My Systems dashboard at `/` with a Current Matches panel — and relocates the existing system editor to `/system`. It **extends** the Flask/Jinja/CSS design system established in Phases 1–4. No new brand, no frontend framework, no chart library, no new dependency. Every token below is inherited from `cfb_system_maker/static/styles.css` and `04-UI-SPEC.md`; this document specifies only what is **new**: the dashboard shell, the systems table, the sparkline, the tabs, the Current Matches panel, the offseason state, and dashboard↔editor navigation.

**Locked sources:** `05-CONTEXT.md` D-01–D-17; REQUIREMENTS DASH-01, DASH-02, DASH-03 (DASH-04 deferred 2026-07-20); `docs/bet-labs-parity-plan.md` §1.1 and §"Phase 4" items 12–13; `04-UI-SPEC.md` (token baseline, D-15 single grading path, D-23 no-framework); `01-CONTEXT.md` D-01 (query-param tabs, full-page GET).

## Layout & Navigation

### Shell

The dashboard does **not** reuse the editor's `.app-shell` (340px filter sidebar + workspace). It is a new two-column shell matching Bet Labs' `dashboard.aspx` (D-12).

**Desktop (≥ 901px)** — align with the existing 900px breakpoint:

```
┌──────────────────────────────────────────────────────────────┐
│ CFB  My Systems                             [ New System ]   │  page header
├───────────────────────────────────────┬──────────────────────┤
│ [My Systems] [Example Systems]        │ Current Matches      │
│ [All Time] [2025] [2024] … [2013]     │ Lines as of …        │
│ ┌───────────────────────────────────┐ │ ┌──────────────────┐ │
│ │ System │ Type │ Record │ Money │  │ │ │ row per match    │ │
│ │        │      │  ROI   │ Last10│  │ │ │ …               │ │
│ └───────────────────────────────────┘ │ └──────────────────┘ │
└───────────────────────────────────────┴──────────────────────┘
```

- Grid: `minmax(0, 1fr)` / `minmax(320px, 420px)`, **32px** column gap.
- Page header spans both columns; **24px** page padding (editor uses 28px on `.workspace` — the dashboard is a new surface and uses the 8pt-grid value).
- Current Matches panel is `position: sticky; top: 24px` on desktop only (discretion), so long system lists do not scroll the week's plays off-screen.

**Narrow (≤ 900px):** single column, stack order **My Systems table → Current Matches**. Both tables scroll horizontally inside a `.table-wrap`-style container; the page never grows sideways.

### Routing & nav (D-09)

| Route | Behavior |
|-------|----------|
| `GET /` (bare) | Dashboard |
| `GET /` **with filter query params** | 302 redirect to `/system` preserving the query string verbatim — old bookmarks/shared links keep working |
| `GET /system` | Existing system editor, unchanged |

- **Editor → dashboard:** the editor's `.brand` block becomes a link to `/`, plus a visible text back-link **My Systems** in the editor header. Do not restyle the editor beyond adding this link.
- **Dashboard → editor:** system name in each table row is a link to `/system?…` carrying that system's state (same query-string load path already used by the editor's "load system" control). Primary CTA **New System** links to bare `/system`.
- No client-side routing. Every navigation is a full-page GET.

Inherited from `04-UI-SPEC.md`. Applies to **new** dashboard surfaces. Do not refactor pre-existing editor paddings that deviate.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Sparkline cell inset; label-to-value nudge inside match rows |
| sm | 8px | Tab-to-tab gap; chip gap; gap between play text and system name in a match row |
| md | 16px | Panel internal padding; gap between tab strip and table; match-row vertical padding |
| lg | 24px | Page padding; panel outer padding; gap between the tab strip block and the table block |
| xl | 32px | Column gap between My Systems and Current Matches |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

**Exceptions:**
- Tables reuse the existing legacy `th`/`td` padding `10px 12px`. Do not restyle global tables to force 8pt purity.
- Sparkline cell: fixed **96px × 24px** SVG box (see Sparkline contract). This is the only fixed non-grid dimension introduced.
- Tab links reuse existing `.tabs a` padding `8px 12px`.
- Current Matches panel min-width 320px / max-width 420px on desktop.

## Typography

Reuses Phase 1/4 roles. Two weights for new elements: **400** and **700**. Legacy `800` is used only where an existing class (`.metrics span`, `button`, `.tabs a`) is literally reused.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label | 12px | 700 | 1.2 | Timeframe tab labels; "Lines as of …" label; week-fallback label; column headers use the existing uppercase 11px `th` rule |
| Body | 14px | 400 | 1.5 | Match-row matched-filter sentences; empty-state body copy; example-system theory text; table cell text where not covered by the legacy 13px `td` rule |
| Heading | 20px | 700 | 1.2 | Page title **My Systems**; **Current Matches** panel heading |
| Display | 22px | 700 | 1.2 | not used on the dashboard — the systems table carries figures at table scale, not chip scale |

- Table cells keep the existing 13px `td` rule; system-name links are 14px / weight 700.
- Play text ("Play Georgia -7") is 14px / weight 700 — it is the actionable line in each match row.
- Matched-filter `describe()` sentences are 14px / 400 and **wrap** (`white-space: normal; overflow-wrap: anywhere`), overriding the global `td { white-space: nowrap }` for that cell only.

## Color

Reuses `:root` tokens — **no new hex values**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` `#f6f8fb` | Page background |
| Secondary (30%) | `--panel` `#ffffff`, `--panel-strong` `#f1f5f9` | Systems table surface and Current Matches panel (`--panel`); table headers, match-row alternating fill, example-system theory block (`--panel-strong`) |
| Accent (10%) | `--accent` `#166f5b` (hover `--accent-dark` `#0d4f41`) | See reserved list below |
| Destructive / negative | `--loss` `#b42318` | Negative Money Won / ROI values; sparkline stroke when the system's final cumulative profit is negative |
| Border / muted | `--border` `#d8e0ea`, `--muted` `#617086`, `--text` `#162033` | Panel borders, table rules, tab inactive state, timestamp and label text, Record values (neutral) |
| Offseason / stale notice | `.stale-warning` amber `#fff4e5` fill / `#f0b429` border | Offseason & week-fallback banner in Current Matches — reuse the existing warning palette, do not invent a second one |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. Primary **New System** button (and its `--accent-dark` hover)
2. Positive signed Money Won / ROI values in the systems table (`.positive`)
3. Sparkline polyline stroke when final cumulative profit is ≥ 0
4. Active tab underline — existing `.tabs a[aria-current]` 2px bottom border (both tab strips)
5. `:focus-visible` outline on dashboard links/buttons (2px solid `--accent`)

**Not accent-colored:** system-name links (`--text`, underline on hover), Record values (neutral fact), play text (`--text` — it is not a status), Current Matches panel chrome, table headers, timestamp, "Copy to My Systems" secondary action, inactive tabs.

**Signed-value formatting** (matches editor conventions exactly, D-11 single source):
- Record as `W-L-P` plus win % — e.g. `177-137-12, 56.4%` — neutral color always.
- Money Won as `$` at profit × 100 with explicit `+` / `−` and `.positive` / `.negative`.
- ROI as a percent with two decimal places, `.positive` / `.negative`.
- Exact zero uses `$0` / `0.00%` with **no** color class.
- A system with **zero matched bets** in the selected timeframe renders `0-0-0`, `$0`, `0.00%`, and an empty sparkline cell (an em dash `—`, not a flat line).

## Sparkline Contract (DASH-01)

The only new visual primitive. Server-rendered inline SVG in the same hand-rolled language as `.cumulative-chart` — **no chart library, no client JS**.

| Property | Contract |
|----------|----------|
| Element | Inline `<svg class="sparkline">` inside the systems-table row, one per system |
| Size | **96 × 24px**, `preserveAspectRatio="none"`, `viewBox="0 0 96 24"` |
| Data | The cumulative-profit series `run_backtest` already produces for the editor's Money Won Over Time chart — running sum of profit × 100 over bets ordered by `(season, week, game_id)`. Same authoritative path (D-11), scoped to the selected timeframe tab. |
| Mark | A **single** `<polyline>`, `fill: none`, `stroke-width: 2`, `stroke-linejoin: round`, `vector-effect: non-scaling-stroke` |
| Color | Stroke `--accent` when the **final** cumulative value ≥ 0; `--loss` when < 0. Reuse `.positive` / `.negative` classes on the polyline. |
| Omitted | No axes, no tick labels, no dots/circles, no zero-line, no fill area, no tooltip, no hover interaction, no animation. A sparkline is a shape, not a chart. |
| Downsampling | If the series exceeds **48** points, evenly sample down to 48 render points. Visual only — it must not alter the Record/Money/ROI figures in the same row. |
| Scaling | y-scale to the series' own min/max with a small vertical inset so a flat series renders as a centered horizontal line, not a clipped edge. |
| Zero / one point | 0 bets → render `—` in `--muted`, no SVG. 1 bet → render a 2px-tall horizontal segment at mid-height in the sign color. |
| Accessibility | `role="img"` with `aria-label="Cumulative profit trend: {signed money won}"`. The sparkline is decorative reinforcement — every figure it implies is already present as text in the same row. |
| Column header | **Trend** (parity's "Last 10" is a different metric; do not label a full-history sparkline "Last 10") |

## Tabs

Both tab strips reuse the existing `.tabs` / `.tabs a[aria-current]` classes and switch by **query-param full-page GET reload** (Phase 1 D-01 precedent). No client-side toggling.

| Strip | Values | Param | Default |
|-------|--------|-------|---------|
| System scope (D-15) | **My Systems** · **Example Systems** | `?tab=mine` / `?tab=examples` | `mine` |
| Timeframe (D-10) | **All Time** · one tab per season present in the data, newest first | `?timeframe=all` / `?timeframe=2025` | `all` |

- Both params compose (`/?tab=examples&timeframe=2024`).
- Active tab: `aria-current="page"` + accent underline. Inactive: `--muted`, no underline.
- **No** "30 Days" / "7 Days" / "Since Built" tabs — `games.csv` carries no kickoff dates (D-10).
- Season tabs may exceed panel width: the timeframe strip scrolls horizontally (`overflow-x: auto`, no wrap) rather than wrapping to three rows.
- The timeframe strip applies to the systems table only. The Current Matches panel is always the current week and is unaffected by it.

## My Systems Table (DASH-01)

Columns, in order:

| # | Column | Content |
|---|--------|---------|
| 1 | **System** | System name as a link to `/system?…`. Below it, in `--muted` 12px, the truncated `theory` first line if present. |
| 2 | **Type** | `Spread` / `Over/Under`, plus ` · Fade` appended when the system's `fade` flag is set (Phase 2 semantics must survive onto the dashboard) |
| 3 | **Record** | `W-L-P, NN.N%` — neutral |
| 4 | **Money Won** | Signed `$`, `.positive` / `.negative` |
| 5 | **ROI** | Signed `%` to two decimals, `.positive` / `.negative` |
| 6 | **Trend** | Sparkline (see contract above) |

- Row order: most recently saved first (existing `saved_at`), matching the editor's load list.
- Long system names wrap in column 1 (override `nowrap` on that cell); all other cells stay `nowrap`.
- Every figure comes from `run_backtest` (D-11). No second grading path, no figures persisted into saved-system JSON.

## Example Systems Tab (DASH-02)

Same table shape and columns as My Systems, with two differences:

- A leading panel note in `--muted` 14px above the table: *"Bundled examples that demonstrate what the tool can filter on. They are not betting recommendations."*
- Each example row expands its written `theory` (D-17) as wrapped 14px body text in a `--panel-strong` block under the system name — the point of the examples is modelling the habit of writing down a hypothesis.
- Row action **Copy to My Systems** (secondary style: `--panel` fill, `--border`, `--accent` text — reuse `.filter-modal__retry` styling language). Examples are read-only (D-14); this is the only way to edit one.

## Current Matches Panel (DASH-03)

Panel heading **Current Matches**, with the fetch timestamp directly beneath it (D-06).

**Row anatomy** — one row per (system × matched upcoming game):

| Field | Content |
|-------|---------|
| Time | Kickoff date + local time from the upcoming file — e.g. `Sat Sep 6, 3:30 PM`. *(The upcoming file carries kickoff date/time even though `games.csv` does not — D-10's date limitation applies to the historical timeframe tabs, not here.)* |
| Matchup | `Away @ Home` |
| Play | **Play Georgia -7** (spread) / **Play Over 52.5** (total) — derived from the system's `side` / `total_side` so displayed play cannot disagree with what would be graded (D-08). 14px / weight 700. |
| System | System name, linked to `/system?…` |
| Type | `Spread` / `Over/Under` (+ ` · Fade`) |
| Details | The matched-filter sentences from the existing `describe()` renderer (D-13), rendered as a wrapped `<ul>` of 14px / 400 lines in `--muted`. No second rendering path. |

- Rows sort by kickoff time ascending, then system name.
- On narrow screens the row collapses to a stacked card (Time → Play → Matchup → System → Details) rather than a horizontally scrolled 6-column table.
- No refresh button, no live fetch — the panel reads the pre-built upcoming file only (D-02, D-06).

### States

| State | Treatment |
|-------|-----------|
| **Populated, current week** | Timestamp line + rows. |
| **Offseason / no upcoming games (D-07 — primary state)** | An amber `.stale-warning` banner with the empty copy, **followed by** the most recent week that has data, under a week-fallback label. Both are shown — the fallback is not a replacement for the notice. |
| **Upcoming week exists but no system matches any game** | Timestamp line + a neutral `--muted` message. Not an error, not amber. |
| **No saved systems at all** | Both columns show the no-systems empty state; My Systems table is replaced by an `.empty-state` block pointing at the Example Systems tab and **New System**. |
| **Upcoming file missing entirely** | Reuse the existing missing-data page state (the same `error="missing_data"` treatment the editor already renders), naming the CLI command to run. Do not invent a new error visual. |
