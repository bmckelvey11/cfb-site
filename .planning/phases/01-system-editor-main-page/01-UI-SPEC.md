# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Flask + Jinja2 + hand-rolled CSS/inline SVG, no build step, no frontend framework (per `.claude/CLAUDE.md` and `01-RESEARCH.md` "no new dependencies" rule). shadcn init gate does not apply: this is not a React/Next.js/Vite project (`components.json`, `tailwind.config.*`, `package.json` all absent — confirmed by directory scan). |
| Preset | not applicable |
| Component library | none — semantic HTML rendered server-side via Jinja (`cfb_system_maker/templates/index.html`) |
| Icon library | none — text glyphs only (e.g. "✕" for remove) plus hand-rolled inline SVG for charts, following the existing `_range_chart()` pattern (`web.py:447`). Do not introduce an icon font/library this phase. |
| Font | `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` — already declared on `:root` in `cfb_system_maker/static/styles.css:15`. No new font this phase. |

**Visual hierarchy:** The stat-chip header (Record/Margin/Money Won/ROI/Grade) is the primary focal point on the loaded-system view — it sits first, uses the largest new type size (22px Display), and is the first thing a returning user checks. The cumulative Money Won Over Time chart is the secondary anchor (the "is this system good" visual). The active-filter sentence list and theory panel are tertiary — supporting context, not the first thing the eye should land on.

## Spacing Scale

Declared values (must be multiples of 4) — applies to **new** elements introduced this phase (stat-chip header restyle, active-filter sentence rows, tab bar, theory panel, cumulative-chart container):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/glyph gaps (e.g. remove-✕ to sentence text) |
| sm | 8px | Chip-to-chip gap in stat header, sentence-row internal gap, tab-item gap |
| md | 16px | Sentence-row padding, theory-panel padding, cumulative-chart container padding, gap between stat-chip header and sections below it |
| lg | 24px | Active-filter panel padding, spacing between major workspace sections (chips → theory → sentences → tabs → tab content) |
| xl | 32px | not used this phase |
| 2xl | 48px | not used this phase |
| 3xl | 64px | not used this phase |

Exceptions: The pre-existing workspace (`.workspace` 28px padding, `.range-chart` 14px padding, table `th`/`td` 10–12px padding, `legend`/`label` styling) already deviates from a strict 8pt grid. Per the project's surgical-change convention, **do not refactor these pre-existing values** — they are out of scope for Phase 1. Only the new elements listed above must follow the 4/8/16/24 scale. The filter-sentence remove control ("✕") reuses the existing `min-height: 36px` interactive-target convention already established by `.check`/`.segmented label` in `styles.css` — not a bare, unpadded inline link.

## Typography

Reuses sizes/weights already declared in `cfb_system_maker/static/styles.css` — no new pixel values introduced.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 700 | 1.2 (matches existing `legend, label` rule) |
| Body | 14px | 400 | 1.5 (matches existing `input`/`button`/sentence-row text size; recommended body line-height) |
| Heading | 20px | 700 | 1.2 (matches existing `h1`; use for new section headings — "Money Won Over Time", tab labels — giving them more hierarchy than the existing 14px `h3`) |
| Display (chip value) | 22px | 700 | 1.2 (matches existing `.metrics strong`, reused for Record/Margin/Money Won/ROI/Grade chip values) |

Only 2 weights across the whole new contract: **400 regular** (body/sentence text) and **700 bold** (labels, headings, chip values). The pre-existing `800` weight on `button`/`.pill` is untouched legacy styling — do not extend `800` to any new element this phase.

## Color

Reuses tokens already declared on `:root` in `styles.css` — no new hex values introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` `#f6f8fb` | Page background |
| Secondary (30%) | `--panel` `#ffffff`, `--panel-strong` `#f1f5f9` | Sidebar, workspace cards, stat-chip card backgrounds, table headers, theory panel, active-filter-sentence row backgrounds |
| Accent (10%) | `--accent` `#166f5b` (green) | Reserved for: positive-sign stat-chip values (Margin/Money Won/ROI when > 0), win pill (`.pill.win`, unchanged), active-tab indicator/underline in the new Results Graph / Past Matches tab bar, existing primary button background (unchanged) |
| Destructive/negative | `--loss` `#b42318` (red) | Reserved for: negative-sign stat-chip values (Margin/Money Won/ROI when < 0), loss pill (unchanged), the filter-sentence remove control ("✕") — this is the only destructive-toned affordance in this phase, and it is non-destructive in effect (reversible URL-state change, no confirmation needed — see Copywriting Contract) |

Record and Grade chips are **neutral** (`--text` on `--panel-strong`), not accent-colored — Record's exact count/percentage is a fact, not a signed value, and the Grade slot is an unresolved placeholder this phase (renders `—` in `--muted`). Do not tint the Record or Grade chip with `--accent`/`--loss`.

Accent reserved for: positive-value stat chips, win pills, active-tab indicator, existing primary "Run System"/"Save System" buttons. Never applied to Record, Grade, neutral labels, or borders generally.

## UI Considerations

Applicable state considerations resolved: 4 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Active-filter sentence list | ✅ covered | When `describe(system)` returns an empty list (no active filters), the panel renders the documented empty-state copy above, matching the existing `.no-saved-systems`/`.no-results` empty-state pattern already used elsewhere in `index.html`. |
| empty | Cumulative "Money Won Over Time" chart | ✅ covered | `_cumulative_chart()` follows the existing `_range_chart()` empty-input convention (`{"points": [], "polyline": "", "zero_y": 75, ...}`) — zero graded bets renders only the zero-line, never a crash or malformed SVG. |
| zero-one-many | Margin/Grade chips for `bet_type == "total"` systems | ✅ covered | Margin renders the same `—` placeholder used for the Grade slot (CONTEXT.md discretion decision) for total-bet systems, keeping the 5-chip header layout stable regardless of bet type. |
| populated | Past Matches tab | ✅ covered | Reuses the existing, already-tested bets table and pill rendering (`index.html:291-324`) unchanged — only reachable via the new `?tab=matches` route split. |
| long-text | Theory display/edit panel | 🧪 backstop | Theory panel wraps with `white-space: normal; overflow-wrap: anywhere`; no server-side character limit this phase. Verify by entering a >280-character theory string and confirming no horizontal overflow or clipping in the rendered panel. |
| overflow | Active-filter sentence list (many simultaneous filters) | 🧪 backstop | List uses `display: grid; gap: 8px` with no max-height/scroll region. Verify visually with 10+ simultaneously active filters (core + several feature filters) that the list doesn't visually collide with the sections below it; if it does, a scroll region should be added in a follow-up, not silently assumed away. |
