<objective>
Fix the `/filter-detail` modal's per-value double-count ambiguity for total-system team/conference (and either-perspective feature) filters. The tuple fan-out in `aggregate_filter_value_rows` is correct and stays (07-CONTEXT.md: one row per matching team-value is the intended per-team breakdown, not a bug). The actual fix is disclosure: add a distinct-game-count field to the `/filter-detail` response, and render a reconciliation caption in the modal driven by the already-computed `overlapping_rows` flag, so the per-value row sum and the true matched-game count are never silently mistaken for each other.

Purpose: today the per-value table's row sum can be ~2x the system's true matched-game count with no explanation visible anywhere in the UI — this reads as a data-integrity bug even though the underlying per-team breakdown is correct.
Output: `/filter-detail` JSON gains a distinct-game-count field; `filter_modal.js` renders a caption in `renderValueTable()` wired to the existing `overlappingRows` flag; stale doc comment corrected.
</objective>
