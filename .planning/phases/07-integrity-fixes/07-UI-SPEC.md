## Copywriting Contract

This phase adds no CTA, no empty state, and no destructive action. The two new copy elements are:

| Element | Copy |
|---------|------|
| Primary CTA | N/A — no new call-to-action in this phase |
| Empty state heading | N/A — no new empty state in this phase |
| Empty state body | N/A |
| Error state | N/A — no new error state in this phase |
| Destructive confirmation | N/A — no new destructive action in this phase |
| **FIX-01: describe() fallback sentence** | `f"{label} filter applied (value: {value})"` — locked by CONTEXT.md decision. Deliberately distinct from the four hand-written branches (`"{label} is {Yes/No}"`, `"{label} is {value}"`, `"the {noun} is {value}"`, `"the {noun} is between X and Y"`) so it reads as "we don't have a nice sentence for this yet," not as a blended-in natural-English sentence. Precedent already in-tree: the existing `"Unknown filter \"{key}\" is unavailable"` branch (`describe.py:63`) proves a visibly-distinct, unstyled sentence is the established pattern — do not invent new wording styles beyond this shape. |
| **FIX-02: filter-detail row-sum reconciliation caption** | Exact wording is implementation's choice (per CONTEXT.md "Specific Ideas" — no wording was locked), but must state, self-contained, both numbers and the reason they differ. Suggested shape: `"These rows cover {D} games — each game counts once per matching value, so rows can sum to more than {D}."` where `D` is the distinct-game denominator (see UI Considerations below). Do not phrase this as reconciling against the editor's top-line Record chip — that chip reflects the full system, while this table reflects `base_system` (candidate filter removed); comparing the two would introduce a third, unrelated number and reintroduce the exact "two numbers silently disagree" failure this fix exists to close. |

## UI Considerations

Applicable state considerations resolved: 2 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| unusual/edge combo | `.active-filters li` (system editor), `.cm-details li` (Current Matches dashboard) | ✅ covered | FIX-01 fallback renders as plain, unstyled text in the same `<li>` structure as every other sentence — no new CSS class, no color change. Distinctness comes entirely from the `"{label} filter applied (value: {value})"` wording. `.cm-details li` already has `white-space: normal; overflow-wrap: anywhere;` (styles.css:1372-1373), so the fallback sentence — which is typically longer than the hand-written branches — wraps safely with no clipping or overflow risk on the dashboard's narrower aside column. |
| double-count / reconciliation | `/filter-detail` modal value table (`filter_modal.js` `renderValueTable`) | ✅ covered | Caption renders inside `controlsEl`, driven by the existing `state.overlappingRows` flag (already computed server-side at `web.py:766-768` and already stored client-side at `filter_modal.js:1702`, currently unused on the categorical path). Suppressed when `overlappingRows` is false (the common case — most filters never double-count) and suppressed on the empty-rows path (`filter_modal.js:824-835`, "No values in range"). No caption when there is nothing to reconcile. |
| new server field required | `/filter-detail` JSON response | 🧪 backstop | The reconciliation caption's denominator (distinct games contributing at least one row) does not exist in any current payload field — `rows`/`domain`/`chart_points` all describe the fanned-out bucket view, and the live-preview `/api/backtest` figure describes a different (draft) system entirely. The route must add one new scalar field (e.g. `matched_games`) computed as the count of distinct `game_id`s that reached `buckets.setdefault(...)` inside `aggregate_filter_value_rows` — NOT `len([g for g in games if matches_system(g, base_system, ...)])`, because `aggregate_filter_value_rows` already `continue`s past games where `resolve_candidate_value` returns `None` (web.py:268-269), so those two counts differ and only the former makes the caption's arithmetic honest. This is marked backstop rather than covered because the exact field name/shape is an implementation choice for the planner, not a locked UI decision — but the *requirement that such a field must exist and what it must count* is locked here. |

## Implementation Notes (non-visual, for planner/executor context)

These are not design-contract items but are recorded here because they directly bound how the visual contract above gets wired up correctly:

- **FIX-01 key round-trip:** The fallback sentence dict must include a `key` in the existing `ff:{feature_key}` shape (matching the pattern every other `_feature_group_sentence` branch already uses) so `_query_href_removing` (`web.py:962`) builds a working remove-link href. It must NOT include an `edit` field — the existing `{% if row.edit %}` guard in `index.html:363` then correctly renders the row as Remove-only (no Edit button), since an uncovered `(op, control)` combo has no modal representation to edit into.
- **FIX-01 never uses `|safe`:** Plain Jinja auto-escape interpolation only, matching the project-wide convention already proven safe by the existing "Unknown filter" branch.
- **FIX-02 driven by the existing flag, not a new one:** `state.overlappingRows` is already correctly computed for exactly the FIX-02 condition (`perspective == "either"` OR (`core:team`/`core:conference` on a total system) — `web.py:766-768`). Wire the caption to this flag rather than introducing a second detection mechanism. This also covers, for free, either-perspective categorical *feature* filters (not just `core:team`/`core:conference`), since those also set `overlappingRows` and reload it on perspective switch.
- **Stale comment to correct:** `filter_modal.js:735-738` (`applyOverlapNote` doc comment) currently asserts categorical/value-table filters "don't need it" — that reasoning applied only to Max ROI's window-summing behavior, not to row-sum disclosure. FIX-02 supersedes this for the new caption; the comment should be updated so a future reader isn't misled into thinking the categorical path was deliberately excluded from all overlap handling.
- **Caption placement:** Render inside `controlsEl` in `renderValueTable()` (`filter_modal.js`), which is already cleared (`controlsEl.innerHTML = ""`) at the top of that function on every rebuild — no manual cleanup needed when perspective changes or the modal reopens.
