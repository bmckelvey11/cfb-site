<objective>
Ship a 4th bundled example system, "Neutral-Site & Indoor Unders" (DATA-01), on the Example Systems tab: a totals/unders system filtering on `neutralSite`, `gameIndoors`, and `venue_dome` (all boolean, all true), with a `theory` field that discloses sample size and significance honestly rather than overstating the finding from `docs/under-team-stats-analysis.md`.

This phase is **not** pure data-only despite CONTEXT.md's framing. Discovery during planning found the new example's `gameIndoors` filter collides with an existing guard test (`tests/test_storage.py::test_no_example_filters_on_provider_weather_or_season_to_date`, D-21) that blocks any example from filtering on a `weather`-group feature, because `gameIndoors` is registered under `group="weather"` in `FEATURE_REGISTRY` (source-gated, can be 0 for future/current-matches games). CONTEXT.md's own "Zero-Match Live Weeks" decision already accepts that this example may show 0 Current Matches in a normal week — that decision is the rationale for a narrow, documented exception to the D-21 guard, not for dropping `gameIndoors` (which is locked by DATA-01/ROADMAP/CONTEXT). So this plan also touches `tests/test_storage.py` (narrow the guard, update the hardcoded example-name list) and, if renamed, `tests/test_web.py`.

Purpose: Give a user browsing the Example Systems tab a 4th, honestly-labeled lead to copy, backed by the project's own statistical analysis rather than a new, unverified data pull.
Output: `cfb_system_maker/examples/neutral-site-indoor-unders.json`, a narrowed weather-filter guard in `tests/test_storage.py`, an updated `EXPECTED_EXAMPLE_NAMES` list, and a verified-against-real-data `theory` field.
</objective>
