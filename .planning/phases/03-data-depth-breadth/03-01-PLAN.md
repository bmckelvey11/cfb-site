<objective>
Deliver DATA-02 breadth: wire new entering-game (to-date) advanced team-stat features — offensive/defensive Success Rate and Explosiveness — into `FEATURE_REGISTRY`, sourced from the already-scraped per-game `advanced_game_stats_{season}.json`, using the exact no-lookahead mechanism as the existing PPA to-date path (D-03, D-06).

## Phase Goal (user story)

**As a** bettor building a system, **I want to** filter on new entering-game advanced stats (to-date offensive/defensive success rate and explosiveness), **so that** I can test edges the current PPA-only to-date registry cannot express.

> Note: the ROADMAP Phase 3 `**Goal:**` line is capability-shaped, not a user story; this story is derived from Success Criterion 2 ("User sees new filter categories or features available when configuring a system").

Purpose: This is the phase's real weight (DATA-01 is thin/verification-only). Advanced stats must be entering-game to-date accumulations, NOT season aggregates — silent lookahead is the single biggest correctness risk (D-06).
Output: 4 new `season_to_date` FeatureDef rows live end-to-end (compute → enrich → registry), each proven no-lookahead by a construct-`GameRecord`-and-assert test.

## Artifacts this phase produces (this plan)

- `enrich._build_running_index` new local `adv` index built from `advanced_game_stats_{season}.json`, passed as `adv=` into `compute_running_stats`.

- `tests/test_features.py` `RUNNING_KEYS` extended by the 4 keys; new registry_version-change assertion.
