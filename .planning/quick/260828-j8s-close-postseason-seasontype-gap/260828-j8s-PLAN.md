# Close the `seasonType` gap — postseason enters the dataset

Every dump on disk is regular season only. `--season-type` defaults to `regular` on
`fetch` and `scrape` while the API's own default is `both`, so ~700 games and ~650 priced
lines (every bowl and playoff game, 2012–2025) are absent. Written up under "Spec-level
gaps" in `docs/data-coverage.md`.

## Probe evidence (run 2026-08-28, before any edit)

```
games 2024 both : regular=3747, postseason=54          -> 3801, exact superset
lines 2024 both : regular=1523, postseason=50          -> 1573, exact superset
game_team_stats 2024 wk1: regular=137 both=187 postseason=50
  both == regular|post : True
```

Two findings, and the second sets the scope:

1. **SEASON mode is a clean superset.** `both` returns exactly the regular rows plus the
   postseason rows. Matches the counts already recorded in `docs/data-coverage.md`.
2. **SEASON_WEEK mode conflates.** Postseason week numbering does not share an axis with
   regular-season weeks, so `both` + `week=1` returns regular week 1 *merged with*
   postseason week 1. `_scrape_season_week` names files `{name}_{season}_wk{week}.json`,
   which has no season-type axis — writing `both` there would overwrite 6 currently-correct
   endpoints with week-conflated content. That is a regression, not a gap closure.

## Scope

**In — 13 SEASON-mode endpoints** (`both`, `--force`, 2012–2025):

| Feeds `build`/`enrich` (8) | Staging only (5) |
|---|---|
| `games`, `lines`, `weather`, `media`, `game_havoc_stats`, `pregame_win_prob`, `ppa_games`, `advanced_game_stats` | `drives`, `elo`, `rankings`, `player_season_stats`, `player_success_season` |

The 8 are exactly the `seasonType`-accepting files `enrich.py:112-126,151,165` reads.

**Deferred — 6 SEASON_WEEK endpoints**: `plays`, `play_stats`, `ppa_players_games`,
`game_player_stats`, `game_team_stats`, `player_success_game`. None feed `build`/`enrich`,
so deferring costs nothing today. Closing them needs a filename axis
(`{name}_{season}_post_wk{week}.json`) plus a separate `postseason` pass — a different
change to `_scrape_season_week`, out of scope here.

## Tasks

### T1 — Capture the pre-scrape baseline
Record, per endpoint per season, the count of rows with `seasonType == "regular"` in every
file about to be overwritten. Written to the task dir as `baseline.json`.
**Verify:** `baseline.json` exists and covers 13 endpoints × 14 seasons (minus known
empty-season floors).

### T2 — Flip the defaults, pin the week path
- `cli.py` `fetch`/`scrape` `--season-type` default `regular` -> `both`
- `cfbd_client.fetch_games_and_lines` and `scrapers.scrape` signature default likewise
- `_scrape_season_week` pins `season_type="regular"` regardless of the caller's value, with
  a comment naming the ceiling and the upgrade path (the `_post_wk` filename axis)
**Verify:** `python -m pytest` green; a `--only game_team_stats` dry read shows `regular`
reaching the week path while `--only games` shows `both`.

### T3 — Re-scrape the 13 SEASON endpoints
`scrape --season 2012..2025 --only <13 names> --force`. `weather` is Patreon-gated and may
error; `_run_endpoint` catches per endpoint so that does not abort the run.
**Verify:** T4.

### T4 — The check that discriminates
Per endpoint per season, against `baseline.json`:
- count of `seasonType == "regular"` is **unchanged**, AND
- postseason rows are **present** (except at known data floors)

A total row count catches neither failure mode. This is gotcha #1 from the prior session:
a pull gained 5,576 rows while silently losing 155 that mattered.
**Verify:** zero regressions reported; `games`/`lines` postseason deltas land near the
+700 / +650 predicted in `docs/data-coverage.md`.

### T5 — `build` + `enrich`, with a feature-identity gate
Re-run `build` then `enrich`. Bowls are terminal within a season: they consume prior-game
state and contribute to nothing downstream in-season, so **features for pre-existing
regular-season game ids must be unchanged**. Any movement means something is wrong.
**Verify:** diff of `features.json` restricted to pre-existing regular-season ids is empty;
new ids appear only for postseason games.

### T6 — Update the docs
`docs/data-coverage.md`: the `seasonType` section moves from open gap to closed-for-13,
deferred-for-6, carrying the probe numbers as the reason. `STATE.md` gets its Quick Tasks
row.
**Verify:** `python scripts/audit_endpoints.py` and `scripts/audit_coverage.py` both clean.

## Constraints

- The working tree carries another session's template/CSS edits. Every commit is
  path-scoped — no `git commit -a`, no bare `git add .`.
- `player_season_stats` / `player_success_season` are season aggregates: with `both` their
  existing rows *change meaning* (totals now include bowls) rather than merely gaining
  rows. Neither feeds `enrich` today, so no lookahead is introduced — flagged in the doc.
- Do not re-read any backtest until T5 passes. Bowls entering the sample shifts every saved
  system's hit rate, p-value and holdout split, and the bowl subsample is small enough to
  invite over-reading.
