# Quick Task: land the coach playstyle analysis as a docs note

Source: in-session analysis (2026-08-27/28) of the five `coach_style_cluster` groups shipped in
`e7efd7c`. Findings currently live only in a published artifact
(https://claude.ai/code/artifact/a436d6fd-e659-4167-b497-fbcc45abc557) and a session scratchpad
that does not survive. This lands the durable copy in the repo.

**Verify command:** `.venv/Scripts/python.exe -m pytest` (no source changes expected, but the
suite is the guard against an accidental import break).

## Design decisions

- **Follows the `docs/data-coverage.md` pattern**: a prose note that records *why* the numbers
  are what they are, paired with a re-runnable script that regenerates them. The note is the
  durable artifact; the script is the reproduction path.
- **One consolidated script**, `scripts/analyze_coach_styles.py`, merging the two scratchpad
  scripts (analysis + charts). It imports `build_coach_style_clusters.py` via
  `spec_from_file_location` so the feature matrix has one source of truth, exactly as the
  scratchpad version did. Analysis-only: writes to `docs/img/` and stdout, touches no package code.
- **Charts committed as PNGs** under `docs/img/coach-style-*.png` (~750 KB total). `docs/img/`
  already exists and holds `dashboard.png`, so this is the established location. Committing them
  means the note renders on GitHub without anyone re-running a two-minute job.
- **No `results.json` committed** — every number it holds is written into the note, and the
  script regenerates it. Committing a derived blob that duplicates the prose earns nothing.
- **Not a package module.** This is a one-off study, not pipeline code; `scripts/` is where the
  other analysis-only entry points live (`audit_coverage.py`, `probe_line_floor.py`).
