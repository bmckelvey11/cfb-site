# Quick Task: `coach_style_cluster` registry feature

Source: in-session playstyle analysis (2026-08-27). k=5 k-means over quality-stripped
(SP+-residualized, within-season z-scored) advanced season stats 2016-2024 produced five
coach playstyle groups. This task ships the label as a team-scoped categorical registry
feature.

**Verify command:** `.venv/Scripts/python.exe -m pytest`

## Design decisions

- **Static career label, embedded as a Python dict** (`cfb_system_maker/coach_style.py`,
  generated by `scripts/build_coach_style_clusters.py`). No sklearn dependency at
  enrich/backtest time; regeneration is an offline script run.
- **Group: `result_lookahead`.** The label is fit on a coach's full 2016-2024 tenure, so a
  2017 game reads a label informed by 2018-2024 stats. Per the project constraint (new
  features must be entering-game or quarantined), it goes in `result_lookahead`: candidate
  search excludes it, UI quarantines it, manual backtest use stays possible. Quality is
  residualized out, so the leak is mild — but the rule is the rule.
- **Join path: reuse `raw_coaches`** (already indexed `(team, season) -> coach record`).
  `enrich._lookup_team_scoped` gets one more special-cased field (mirrors `coach_name`):
  build the coach's full name, look it up in the embedded dict. Unknown coach (<3 seasons
  in window, pre-2016-only, FCS) -> None, fails closed like every other feature.

## Steps

1. `scripts/build_coach_style_clusters.py` — deterministic generator: load
   `advanced_season_stats_{2016..2024}.json` + `coaches_{...}.json`, z-score 13 style
   features within season, residualize on SP+ overall, aggregate per coach (games-weighted,
   >=3 seasons), k-means k=5 (`random_state=0, n_init=25`), name clusters by profile
   signature (greedy: min pass rate -> option_ground; max def stuff -> attack_defense;
   min def explosiveness -> bend_dont_break; max off success -> pass_first_efficient;
   remainder -> balanced_spread). Writes `cfb_system_maker/coach_style.py`.
2. Run generator -> `cfb_system_maker/coach_style.py` (~189-entry dict).
3. `features.py`: `FeatureDef("coach_style_cluster", ..., "result_lookahead",
   "raw_coaches", "coach_style_cluster", "team_season", "categorical", team_scoped=True)`.
4. `enrich.py`: handle the field in the `raw_coaches` branch of `_lookup_team_scoped`.
5. Tests (`test_enrich.py`): known coach -> label, unknown coach -> None; registry
   uniqueness already covered by `test_features.py`.
6. Full pytest, SUMMARY.md, STATE.md quick-tasks row, commit, push.

## Done when

- `enrich_games` emits `home_coach_style_cluster` / `away_coach_style_cluster` for a
  fixture game whose coach is in the mapping.
- Full suite green.
