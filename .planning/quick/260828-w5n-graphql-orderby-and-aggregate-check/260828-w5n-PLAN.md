# Quick Task: fix GraphQL `orderBy`, verify dumps against aggregate counts

Both items came out of reading https://graphqldocs.collegefootballdata.com.

## 1. `orderBy` has never been applied

`_paginate` emits `order_by: {id: asc}` and gates it on `"order_by" in table.args`. Live
introspection and the docs both say the arg is **`orderBy`**, so the gate is always false —
every paginated pull has run `limit`/`offset` **unsorted**, which the docs explicitly warn
against. The string was wrong twice: probing live shows the enum must be uppercase
(`{id: ASC}`); `asc` is rejected outright.

Not currently corrupting data — fresh pulls of `teamTalent` (2,413) and `coach` (1,842)
match their aggregate counts exactly. The exposure is the 100+ page tables (`game` is 113
pages at 1k/page), where an unstable page boundary is silent.

## 2. Aggregates give the audit real ground truth

20 of the 35 default tables expose `{table}Aggregate { aggregate { count } }`. That turns
GraphQL coverage from "a file exists" into "the row count matches the source" — something
the REST side has no equivalent for. The other 15 (`gameTeam`, `poll`, `ratings`,
`transfer`, …) stay file-existence only, and the audit must say so rather than implying
they were checked.

Counting disk rows must not parse the files: `game.json` is 103 MB and would balloon in
memory. `_write` dumps `json.dumps(rows, indent=2)`, so every top-level row starts at a line
that is exactly `  {`. Verified on `teamTalent`: line count 2,278 == parsed length 2,278.

## Tasks

1. `graphql_client._paginate` — `orderBy` + uppercase enum, gated on the real arg name.
2. `scripts/audit_endpoints.py` — per-table row-count check for the tables with an aggregate
   variant. Count-drift is a **warning, not exit 1**: a stale dump is a refresh decision,
   not a wiring bug. Unreachable schema still degrades to a note.
3. Network-free tests for both: that a table advertising `orderBy` emits it, and that the
   count check reports drift without changing the exit code.

## Done when

A fresh pull of a paginated table still matches its aggregate count with ordering on (proves
the fix didn't break pagination), the audit prints per-table drift for the 20 checkable
tables, and the suite is green.
