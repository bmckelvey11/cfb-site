# Quick Task: registry features from the newly registered endpoints

The 10 endpoints registered in `260828-m3k` are scraped to `data/raw/` but nothing reads
them. This wires the usable ones into `FEATURE_REGISTRY` + `enrich`.

**Verify command:** `python -m pytest`, then `enrich` over real data and confirm non-null
coverage per feature.

## The lookahead call, and why most of the new data is skipped

`core_ratings` rows carry `throughSeasonType: "postseason"` — they are **final** season
ratings. Same for `srs_expanded`. Using season S's rating on a season S game would leak the
result of the game being bet. The repo already has the fix pattern: `prior_off_wepa` indexes
season S-1's file under key S (`_index_prior_player_agg`), so a season-S game reads S-1 only.
All rating features here follow it. Nothing goes in `result_lookahead`.

### Skipped, deliberately

- **`coach_seasons`** — season aggregates (wins/losses/`pollResume`/`draftFollowingSeason`),
  so same-season is lookahead, and the prior-season version duplicates what `records` and the
  `season_to_date` running stats already give. `draftFollowingSeason` is lookahead by
  construction.
- **`cfp_playoff` / `cfp_games` / `cfp_participants`** — pregame-legitimate (seed and
  committee rank are known before the game), but they cover ~64 games out of 13k. A system
  filtered on them has no sample. Register as features when someone actually wants a
  playoff-only study.
- **`conference_affiliations`** — team classification per season is already covered by
  `conference_classification` (`raw_conferences`) and `team_conference` (`raw_teams`).
- **`coach_profile` / `coach_tenures`** — `on_demand`, nothing on disk to join.

## Features to add (5)

| Key | Group | Source | Value |
|---|---|---|---|
| `prior_core_overall` | `team_preseason` | `core_ratings_{S-1}` | prior-season core overall rating |
| `prior_core_offense` | `team_preseason` | `core_ratings_{S-1}` | prior-season core offense rating |
| `prior_core_defense` | `team_preseason` | `core_ratings_{S-1}` | prior-season core defense rating |
| `prior_srs_rating` | `team_preseason` | `srs_expanded_{S-1}` | prior-season SRS, FCS included |
| `conference_change` | `team_preseason` | `conference_changes_{S}` | team's first season in a new conference |

`conference_change` is same-season on purpose — realignment is known before kickoff.

## Tasks

1. `features.py` — two new `SourceKind`s (`raw_prior_team_season`, `raw_conference_change`)
   and the 5 `FeatureDef`s.
2. `enrich.py` — `_index_prior_team_season` (S-1 file keyed under S, bucketed by
   `source_file` so both rating files share one indexer) and `_index_conference_change`
   (per-season team set). Wire both into `_build_indexes` + `_lookup_team_scoped`.
3. Tests mirroring `test_enrich_prior_off_wepa_uses_prior_season_only`: a same-season
   sentinel that must never surface, and absent-file → `None`.
4. Re-run `enrich` on real data; report non-null coverage per feature.

## Done when

Suite green, `registry_version()` changes (sidecar staleness warning fires as designed), and
each new feature has measured non-null coverage on real games — a feature that resolves to
`None` everywhere is a wiring bug, not a feature.
