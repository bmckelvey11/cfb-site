## Description
Implements the greedy/beam search loop: expands candidates from MVP-002, evaluates each using `run_backtest_summary` only (never full `run_backtest`), prunes by minimum sample size and positive ROI, and ranks survivors deterministically. Performance-critical and leakage-critical core of the feature.

## Acceptance Criteria
- [ ] Beam search parameters have explicit defaults: `beam_width=100`, `top_k=20`, `min_decided_bets=100`, `alpha=0.05` — all overridable, all reported back to the caller as "effective values" used.
- [ ] **Every** candidate evaluated during expansion/pruning/ranking uses `run_backtest_summary` (match+grade, no permutation-test overhead) — `run_backtest` (full, 1000-iteration permutation test) is **never called during the beam loop** (enforced structurally: beam loop function does not import/call `run_backtest`, or a test spy asserts zero calls).
- [ ] Rank/prune ordering is exactly: **in-sample Wilson lower bound → ROI → decided-bet count → canonical candidate identity** (last as deterministic tie-break, from MVP-002's identity function).
- [ ] Candidates below `min_decided_bets` or with non-positive in-sample ROI do not advance past pruning.
- [ ] All expansion, quantile-lookup, matching, pruning, and ranking operate on **in-sample games/feature rows only** — the beam loop's function signature takes only the in-sample split (from `split_holdout`), never the full unsplit dataset or holdout split.
- [ ] Search-scope config (season range via `--season`, bet type spread/total, max filter dimensions) is applied and demonstrably bounds the candidate space and results.
- [ ] Output is an ordered list of surviving candidate `SystemFilter`s (top-K, deterministically ordered) plus `candidates_tested` count (N — every candidate evaluated during in-sample discovery, provenance only, not yet a BH input).
- [ ] `tests/test_search.py` gains: min-sample-gate test; in-sample-only evaluation test (holdout rows never reach the beam loop — fixture where holdout-only signal would change ranking if leaked, confirm it doesn't); `run_backtest_summary`-only call-count/spy test (full `run_backtest` call count is zero during this stage); deterministic ranking test (same fixture → same top-K list and order, twice).

## Technical Notes
- File: `cfb_system_maker/search.py` (extend from MVP-002).
- Reuses `run_backtest_summary` from `backtest.py` as-is. Note it does NOT currently return Wilson bounds — likely needs a summary-level Wilson-bound call using MVP-001's counts-based helper, or reuse `_wilson_interval` directly on `(hit_rate, decided)` since that function is already counts-based.
- `_wilson_interval` in `backtest.py` is currently module-private — needs either exporting or a small public wrapper; minor `backtest.py` touch-point even though MVP-001 is the primary stats-functions ticket.
- Beam mechanics: standard beam search — at each step, expand every surviving candidate by one more compatible dimension (per MVP-002's grammar), evaluate all expansions, prune, keep top `beam_width`, repeat until max filter dimensions reached or no legal expansions remain.
- This is where the "hour-plus" performance risk lives if `run_backtest_summary` is O(all games) per call with no caching — with `beam_width=100` and up to 6 expansion rounds this is still thousands of summary evaluations; confirm via MVP-006's benchmark, not assumed fast here.
