## Description
Extends `SavedSystem` and its persistence functions with provenance fields, following the exact backward-compatible default pattern already used for `theory`/`fade`. Adds an optional `--save NAME` flag to the `search` CLI command so a search result can be persisted and exercised end-to-end.

## Acceptance Criteria
- [ ] `SavedSystem` gains `source: str = "manual"` and `search_candidates_tested: int | None = None`.
- [ ] `save_system` gains keyword-only provenance arguments (e.g. `source="manual"`, `search_candidates_tested=None`) and serializes them in `_system_to_dict`.
- [ ] `load_saved_system` and `load_example_system` both read these fields with graceful defaults (`payload.get("source", "manual")`, `payload.get("search_candidates_tested", None)`) — matching the existing `theory`/`fade` precedent exactly.
- [ ] Given an old saved-system JSON file with no `source` key, loading it defaults `source="manual"` and `search_candidates_tested=None` — no migration script, no error.
- [ ] Existing callers of `save_system` (CLI `_backtest --save`, web `/system` save flow) are unaffected — continue producing manual systems with `search_candidates_tested=None`, without needing to pass the new kwargs.
- [ ] A search-found system, when saved via the new `search --save NAME` CLI flag, round-trips through `save_system`/`load_saved_system` with `source="search"` and the correct `search_candidates_tested` value intact.
- [ ] `tests/test_storage_systems.py` (or `test_storage.py`) gains: old-JSON-defaults-to-manual test; search-provenance-round-trip test; existing manual-save-flow-unaffected regression test.
