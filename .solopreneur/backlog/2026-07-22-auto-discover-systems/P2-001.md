## Description
An opt-in, explicitly-triggered LLM call that summarizes already-computed top-K search results in plain English. No LLM involvement in scoring/selection — narration only, rendered as a collapsible text block.

**Gap resolved**: P1 (P1-001/P1-002) only badges *already-saved* search systems — it did not add a live "view search run results" web page. Resolved by persisting a full run artifact (`SearchRun`/`SearchRunFinalist`, via new `search --save-run NAME`) and adding a new `GET /search-runs/<name>` view for it, rather than narrating a single already-saved system's results.

**Design note on "theory-panel-style"**: the existing `theory-panel` (`index.html:327-332`, `styles.css:310-320`) is visually reusable (border/heading/padding convention) but is **not currently collapsible** — no `<details>`, no JS toggle, gated only by server-side Jinja conditional. The collapsible opt-in trigger interaction this story requires is new to the codebase, not a copy of an existing pattern. Reuse the CSS classes for visual consistency; build the trigger/expand/fetch JS as new.

## Acceptance Criteria
- [x] Narration triggers only on an explicit user action ("Narrate results" button/link) — **never automatic on page load**.
- [x] Exactly **one LLM call per explicit request** — cost stays visible/bounded, no chained/looping calls.
- [x] The LLM call uses **only already-computed stats** as input (candidate list, holdout results, raw/corrected p-values, grades) — no LLM involvement anywhere in the scoring/ranking/selection path from MVP-002 through MVP-004.
- [x] Rendered `theory-panel`-styled, **appended to the existing results display** — no new screen/route beyond what's needed to view search results at all (see gap note above). **Deviation:** not collapsible via `<details>` as originally specced — final review found the disclosure toggle could get trapped behind the post-success disabled button, so it ships as a plain always-visible panel instead. Same visual reuse of `.theory-panel`, different interaction.
- [x] Failure/timeout of the LLM call degrades gracefully — results display remains fully usable without narration, doesn't block or error the rest of the page. Verified live in browser (502 path).

## Technical Notes
- Stack choice (which LLM/API, cost controls, prompt template) is unspecified in the spec — needs a design/engineering decision pass before implementation.
- Likely a new small route (e.g. `POST /narrate`) plus a fetch-triggered JS handler, consistent with the project's plain vanilla JS/fetch modal convention (per `.claude/CLAUDE.md`: "popup modals must be built with plain JS/fetch, consistent with existing index.html/compare.html pattern").
