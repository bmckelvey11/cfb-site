## Description
Wires MVP-002 through MVP-004 into a new `python -m cfb_system_maker search` CLI command with the documented flags, required-holdout validation, and the two structured non-zero-exit error paths (`missing_data`, `missing_features`).

## Acceptance Criteria
- [ ] New CLI command: `search --data-dir data --holdout-season 2025 [--season 2019 ...] [--max-filters N] [--bet-type spread|total] [--beam-width 100] [--top-k 20] [--min-decided-bets 100] [--alpha 0.05]`, added to `_build_parser` and dispatched in `main`.
- [ ] Given no built `games.csv`, `search` writes `error=missing_data` plus actionable rebuild guidance to **stderr** and exits **non-zero without a traceback**.
- [ ] Given no `processed/features.json`, `search` writes a clear non-zero `missing_features` error to stderr naming the `enrich` command, and exits non-zero without a traceback — core-filter-only mode is **not** an implicit fallback.
- [ ] `--holdout-season` is **required** (argparse enforces presence) — missing it is a usage error, not a silent all-data default.
- [ ] Given a holdout season that is unknown (not present in the built data) or that would leave **zero** in-sample seasons after `--season` scope filtering, `search` refuses with a clear non-zero error rather than silently proceeding with `split_holdout`'s existing silent-empty-set behavior.
- [ ] `--season` scope is applied **first**, then `split_holdout` — order matches spec exactly.
- [ ] CLI reports the effective values used for `beam_width`, `top_k`, `min_decided_bets`, `alpha` (even when defaulted).
- [ ] Stdout summary includes `candidates_tested`, `finalists_graded`, and per-finalist raw/corrected p-values — using the exact field name **`search_candidates_tested`** for the candidates-tested count (not `candidates_tested` alone), matching the field name P1's UI will later read from `SavedSystem`.
- [ ] Given the same fixture data and flags, two consecutive runs produce **byte-identical ranked output**.
- [ ] `tests/test_cli.py` gains: missing-`games.csv` → non-zero + `error=missing_data`; missing-`features.json` → non-zero + `missing_features` naming `enrich`; output-includes-expected-fields test; byte-identical-repeat-run test.

## Technical Notes
- File: `cfb_system_maker/cli.py` (modify — add `search` subparser in `_build_parser`, add `_search(args)` dispatch function in `main`, following the existing `_backtest`/`_enrich` pattern).
- File: `tests/test_cli.py` (modify).
- First CLI command in the project with a **structured `error=` stderr contract** — existing `backtest` does not have this. Do not retrofit `backtest`, out of scope for this ticket.
- Reference `web.py`'s existing `{"error": "missing_data", "message": ...}` JSON pattern for error string vocabulary, but this is CLI stderr text, not a Flask JSON response — no shared code path expected, just consistent naming.
- `load_features` (used in `_backtest`'s CLI path today) currently raises `FileNotFoundError` on missing `features.json`, which `_backtest` silently swallows. `search` must instead treat this as a hard `missing_features` error — a deliberately different behavior from `_backtest`'s existing leniency. Flag this divergence in code comments so it isn't "fixed" to match `_backtest` later.
