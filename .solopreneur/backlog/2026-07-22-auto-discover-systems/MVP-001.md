## Description
Add two standalone statistics functions to `backtest.py`, beside the existing `_hit_rate_z_test`/`_wilson_interval`: an exported analytic one-sided p-value helper usable from summary counts (no `BetDetail` list required), and a Benjamini-Hochberg correction function. These are pure functions with no dependency on search machinery — foundational for MVP-004.

## Acceptance Criteria
- [ ] New function computes a one-sided analytic p-value from `(wins, decided, break_even_rate)` or equivalent summary counts — usable directly from `run_backtest_summary`'s output dict, not requiring full `BetDetail` construction.
- [ ] New function's result agrees with the existing `SystemStats.p_value` (`_hit_rate_z_test`) for the same decided-bet counts — i.e., it is a refactor/extraction, not a divergent second implementation.
- [ ] New function `bh_correct(p_values: list[float], alpha: float = 0.05) -> list[dict]` (or equivalent) implements Benjamini-Hochberg: sort ascending, compare each to its **rank-scaled threshold `i/K × alpha`** (K = batch size) — explicitly NOT a flat Bonferroni `alpha/K` division.
- [ ] Function returns, per input p-value, at minimum: `raw_p`, `corrected_p`, `bh_significant` — mapped back to original input order/identity, not just sorted order.
- [ ] Adjusted p-values are **monotonic after rank restoration** (standard BH step-up property holds post reordering).
- [ ] Ties in p-value are handled per standard BH tie convention and covered by a dedicated test case.
- [ ] This function is **never called from `compute_grade`** — no call site in `compute_grade` or any path feeding the letter-grade composite.

## Technical Notes
- File: `cfb_system_maker/backtest.py` (modify — add functions near `_hit_rate_z_test`, `_wilson_interval`).
- File: `tests/test_backtest.py` (modify — add BH known-value test, BH tie-case test, monotonicity-after-restoration test, analytic-p-agrees-with-existing-p_value test).
- Likely extraction: factor the p-value math out of `_hit_rate_z_test` into a counts-only helper (e.g. `_analytic_p_value(wins, decided, break_even_rate)`) that both the existing full-stats path and the new summary-count path call, avoiding duplicated math.
- Keep signature summary-count-based (ints/floats in, not `BetDetail` lists) — must be callable from `run_backtest_summary`'s dict output in MVP-004 without constructing full bet detail objects.
- BH is a **batch** operation over a fixed-size list — design as running once over K finalists, not incrementally per-candidate.
